# BookOrbit 上游升级检查清单

每次把官方新 tag 合入定制分支时使用。完成状态要附命令、测试结果或部署日志，不能只勾选而没有证据。

先阅读 [定制补丁索引](CUSTOM_PATCH_INDEX.md)，逐项核对BO-C01至BO-C09，并将上游已覆盖功能与仍需保留补丁分别记录。独立数据库套件见相邻postgresql-spk项目。

## 上游版本与工作区

- [ ] 从官方仓库确认新正式 tag、提交哈希和发布日期。
- [ ] `git fetch upstream --tags` 后确认 tag 指向与官方发布一致。
- [ ] 确认当前工作区干净，定制分支和升级分支名称正确。

## 中文书源后台任务

- 确认迁移包含 `book_source_jobs` 及其用户历史、活动队列和来源去重索引。与上游合并时检查 Drizzle 迁移序号和 snapshot 分支冲突，不可仅按文件名覆盖上游迁移。
- 测试提交后关闭页面，再次打开可见任务；检查取消、重试、权限撤销以及同书重复提交。
- 强制中断下载实例，确认子进程退出，过期租约能被处理；入库未确认的任务不能自动重下。
- 固定番茄运行材料版本与 SHA-256；变更上游下载器时重新执行实际 EPUB、章节完整性、成功/取消/超时及父进程退出测试。
- 使用独立 PostgreSQL 测试库执行后台任务集成测试，不在生产数据库运行会重建表的测试。
- 执行 `pnpm --filter client validate:locales`，并检查新增英文键是否同步补齐简体中文。该校验允许其他语言目录稀疏，不能代替简体中文完整性检查。

## 下载故障恢复专项

- 使用`scripts/book-source/verify-direct-recovery.mjs`运行实际编译下载器，而非仅mock fetch。脚本仅使用新建临时目录、2MiB合成载荷和回环测试代理，不写书库或数据库。指定`BOOK_SOURCE_APP_ROOT`为编译服务端package.json路径，Node24或目标NAS运行时执行。
- 覆盖socket中断重试、确认部分文件落盘后SIGKILL并启动新进程续传、响应ETag变更、错误Content-Range与无校验器部分文件拒绝恢复。成功后校验SHA256，失败后有界等待异步清理。测试源在部分传输时主动停住，不能依靠固定毫秒延迟恰好杀在传输中间。
- `scripts/book-source/verify-nas-job-recovery.mjs`只允许`BOOKORBIT_VERIFY_ISOLATED=1`及隔离数据库URL。它创建随机`bookorbit_recovery_verify_*`临时库，执行原0125/0126迁移，并在finally删除临时库。迁移文本JSON由仓库迁移文件生成，传入容器`/tmp/bookorbit-job-recovery-migrations.json`，不得改用生产数据库执行。
- 区分两种恢复：直链文件有安全HTTP校验器时可续传；章节后台任务下载中断标记失败后由用户重试。入库阶段中断不可自动重下，必须先核对书库，旧worker不得覆盖新状态。
- 对206/416续传响应，如果源站明确返回不同ETag或Last-Modified，拒绝拼接，关闭响应并清理暂存；不能只验证字节起点和总长度。
