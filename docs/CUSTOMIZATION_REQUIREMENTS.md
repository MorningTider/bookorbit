## 功能要求

| 范围             | 需求与验收条件                                                                                                                                                                    |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TXT 上传         | 网页上传流程接受 TXT，不要求上传时转换。上传成功后仍使用 BookOrbit 的书籍、权限和文件管理流程。                                                                                   |
| TXT 扫描         | 扫描器能识别 TXT，编码包含 UTF-8、GB18030/GBK、UTF-16 等常见格式；扫描不可把同一本书的 TXT、EPUB 建成两本书。                                                                     |
| TXT 元数据       | 从文件名和正文中提取可用标题、作者等信息；提取失败时仍允许用户编辑或运行元数据搜索。                                                                                              |
| TXT 转 EPUB      | 由用户在书籍详情或操作菜单中主动启动。提供编码、章节识别、单章节模式等设置；有现存 EPUB 时默认不覆盖。转换后的 EPUB 与原 TXT 关联到同一本书，并共享书名、作者、封面及其他元数据。 |
| 阅读和下载格式   | 网页端可选择 TXT 或 EPUB。Android 端按现有行为继续使用 EPUB，不把 TXT 客户端阅读列为本轮目标。                                                                                    |
| 自动元数据获取   | 导入、扫描新增的书籍可自动进入元数据获取流程；用户能配置或关闭自动获取，并能查看失败后重试或手动获取。漫画和有声书走统一可配置流程，提供商缺少特定字段时保留已有值。              |
| 豆瓣提供商       | 用于图书元数据搜索和匹配，能展示字段来源、匹配结果和失败原因；封面链接不能因来源站点不可达而静默丢失。                                                                            |
| 番茄元数据提供商 | 仅描述元数据搜索与匹配能力，不等同于正文下载。                                                                                                                                    |
| 其他中文元数据源 | 评估并按可用性逐项实现百度百科、七猫、起点等来源；须遵循来源站点的公开接口、使用条款和访问限制。                                                                                  |
| 封面图片         | 解决提供商有封面但 BookOrbit 页面未显示的问题。图片方案需要说明外链、请求失败和回退行为；不得无上限永久缓存所有来源图片。                                                         |
| 书源检索和下载   | 用户希望在同一个 BookOrbit 服务中检索并下载合法可获取的图书或漫画，下载后保留书名、作者、封面等元数据并进入书库。不能把元数据搜索说成正文下载。                                   |
| 下载来源边界     | 只实现公开、授权或明确允许下载的来源。不得绕过登录、付费、DRM、访问控制或来源站点限制。                                                                                           |
| 漫画             | 保留 BookOrbit 已有漫画能力；对用户要求的来源搜索、下载、封面与元数据处理逐项验证。                                                                                               |
| 有声书           | 验证 M4A 等格式导入、扫描、播放文件关联、时长和嵌入式标签读取。外部元数据提供商只能补充其实际提供的字段。                                                                         |
| 中文界面         | 核对定制新增页面、按钮、校验提示、空状态、错误提示和设置项的中英文资源；逐页检查现有页面未翻译文本。                                                                              |
| 群晖部署         | 先隔离验证，再切换正式服务；保留数据库和书库备份、部署日志、健康检查及回滚步骤。                                                                                                  |
| 原生 SPK         | 目标是自动构建、上传到 DSM 套件中心、安装、启动、查看日志、验证后切换；不要在未经隔离测试时覆盖当前服务。                                                                         |

## 重要验收边界

- TXT 上传成功不代表 TXT 已自动转换。转换必须由用户显式触发。
- TXT 和 EPUB 是同一本书的不同格式，修改元数据或封面后两种格式应保持一致。
- “搜索到书籍”不代表“可以合法下载正文”。界面和文档必须区分元数据搜索、文件解析和正文下载。
- 自动刮削需有配置、日志、失败状态和重试路径，不得阻塞大批量扫描或一次性把整个书库载入内存。
- 任何新列表、搜索和队列逻辑都要支持数万本书的用户书库，并遵循项目的用户数据隔离约定。
- 部署在开发机、Docker 或模拟环境通过检查，不代表已在群晖目标机完成验证。

### 独立数据库部署补充（2026-10-27）

共享PostgreSQL由独立原生SPK维护，不是数据库Docker包装。BookOrbit迁移须先一致快照备份、独立恢复并逐表核对，再验证扩展、非超级用户、20连接池与角色24额度、详情并发、书籍Range读取以及开机私网监听恢复。迁移辅助代码纳入BO-C10，后续同步上游时复核配置名、镜像入口、连接池上限与迁移ledger，不能直接复用旧版本的固定配置假设。生产切换与BookOrbit本身原生SPK属于后续独立步骤。

原生PG迁移验收新增：最终切换须停写后再次一致备份，校验最新数据；永久部署配置移除旧postgres服务及依赖，保留镜像/JWT/挂载；停用旧DB后保留全部卷；健康确认前可恢复原应用，确认后新写入须通过反向迁移保留。默认只读检查，不以在线预检快照代替最终生产快照。工具和证据见SYNOLOGY_PG_MIGRATION.md。

原生应用运行库要求：媒体/Python 工具须在 DSM 普通套件身份下验证，不能仅以宿主 glibc 版本字符串推断兼容性。私有运行库不覆盖系统文件，不将私有 libc 注入主 Node；Python 子进程须重新进入配套加载器。保留中文 CMap、字体及 HTTPS 校验，组件版本与源码须可追溯。构建候选在依赖锁定、许可证源码审计、完整应用业务和 SPK 生命周期验收完成之前不得发布。

容器转原生应用的路径迁移要求：完整审计文本及JSON旧路径；只改写已审查字段；计划绑定映射及快照并检查目标碰撞；先在原生PG独立副本验证整笔事务回滚、成功后无残留、旧计划拒绝。文件存在性与访问权限须分别以原身份、新套件身份验证。禁止仅改主书籍表、直接全库字符串替换、在NAS根目录创建通用/books或/data链接，以及递归放开整座书库写权限。

原生应用生产切换要求：最终停写快照恢复到新数据库副本，在隔离库身份下事务改写容器路径并再次完整审计，通过后提升新库。保留原生产库、容器、配置和应用数据；保留JWT及加密密钥。新服务健康确认后禁止自动回到旧库，以免遗漏新写入。普通套件账号只对ebook子目录授予写权限，其余书库只读；日常SPK升级沿用现有生产service.json，不能重新运行一次性Docker迁移工具。

全前端中文要求补充（2026-10-29）：简体中文下的固定界面、脚本生成标签、图表坐标/提示、列配置、引导和错误兜底统一通过国际化键显示。保留用户书名、自定义字段、品牌和格式标识，不修改数据库字段/过滤值。上游合并须回归语言切换的即时更新，不能只扫描Vue静态模板。动态脚本审计候选应追踪消费者，不能简单把所有英文常量替换为中文。

原生启动恢复要求（2026-10-29）：临时PID/退出记录只需私有权限与原子替换，不要求断电持久化；配置、数据库与备份的同步策略保持原样。健康必须同时满足专用UID、启动时间、监督程序身份、可信Node子进程及HTTP数据库健康。慢存储启动允许最多600秒等待，监督程序已明确退出时提前失败，不无限等待。新增验收须包含超过旧180秒期限的真实延迟HTTP就绪、正常启停、崩溃恢复、无孤儿进程及外部占用端口拒绝；延迟就绪测试不等同强制RAID故障或整机重启测试。

自用正式包要求（2026-10-29用户确认）：自用稳定交付与公开发布分开。正式包须由明确的build-private-stable-spk.py入口生成，保留源码/清单/控制器/迁移和真实生产收据绑定、普通账号生命周期检查、私有配置、备份及正常DSM上传升级；不能仅手改INFO去掉Beta。公开发行材料以后单独处理。

2026-10-29 电子书组织方式修复：按用户选择，将既有 ebook 书库从 book_per_folder 受控迁移为 book_per_file，每个独立 TXT 一本；EPUB/PDF 等继续遵循同一组织配置，明确附属的同书版本保留关联。原目录不自动等同系列。原书 ID 留给原主文件，保留文件 ID、阅读进度、阅读会话和用户阅读状态，音频书库不变。新建书库可选择组织方式，既有书库切换须先备份、预演并核验关联数据，不能只改配置或直接删除重扫。TXT 装饰线或网址不能成为标题，应回退到文件名。

2026-10-29新增作者资料需求：作者搜索、候选对比、链接查询及自动补全需要支持百度百科、豆瓣、番茄、起点等国内来源，不能将已支持图书元数据误报为作者已支持。保留来源身份和可配置字段优先级，区分同名作者、目录署名与真实作者主页；仅获取公开可访问数据，访问验证、限流和结构变化须提示失败，不记作空结果或缓存成功。简介、头像、出生资料按来源实际能力返回，未知字段不编造。新增来源需进入共享类型、后端注册/缓存/DTO、中文设置及前端候选/链接解析、自动补全和实机页面验证。现有记录优先保留，不因新增来源自动覆盖已锁定或手工资料；完成后以源码构建自用正式SPK交付，公开发行仍后置。

2026-10-29转换格式要求：TXT转EPUB必须保持一本书、两个附件。转换接口成功后，文件监视、定向扫描、全量扫描均不能把转换文件另建书目，原TXT与EPUB阅读记录均保留。已经因缺陷拆分的书目不得直接删除造成进度/会话丢失，须通过可审查的应用操作修复。

## 2026-10-31 小说搜索与下载体验补充

- 搜索支持部分书名关键词，多结果展示，不复用单书元数据匹配的严格筛选。
- 展示实际书名、作者、书源、封面、分类和可展开简介，提供搜索、空结果、入队反馈及移动布局。
- 页面不让用户手选单个下载来源，自动聚合设置中开启且具备下载适配的来源。
- 设置 → 元数据 → 提供商 → 小说下载来源：番茄与起点分别有独立下载开关，关闭不影响元数据刮削。前提为启用对应提供商；七猫尚无正文适配，不能仅靠开关宣称支持下载。
- 结果按自身来源下载，后端校验开关，覆盖新任务、重试和后台执行。
- 所有新文案国际化，维护共享类型、严格 DTO、权限、持久化与回归，防止上游同步时被覆盖。

## 2026-10-31 原生下载与新书入库恢复要求

- 原生番茄链路必须经 Node guard 实际启动并完成正文下载、EPUB 校验和入库，不能以搜索、预览或下载器直启替代验收。guard 仅继承必需运行库路径，隔离 HOME 和固定 PATH，不透传数据库、JWT 或 LD_PRELOAD。
- 新书上传和已有书追加格式均须在发布前登记共享自写保护，持续到归属事务提交，成功和失败均释放。文件监视不能抢先建书；不能以固定延迟代替提交边界。
- 登记失败仅清理临时文件，不删除已经发布的有效文件。入库中断保持需人工核对，不能后台无条件重下。
- 页面提供“核对入库后重试”，确认目标未入库且没有残留文件后，重试原任务。严格请求仅接受显式 true，并检查所有权、书库编辑权限、来源开关、失败且未关联结果、重复任务与队列限制。正常进行或已完成任务不能使用该通道。
- 完成任务可跳转查看书籍；用户错误不暴露 SQL。恢复原空书目须经正常上传路径复用，不直接写数据库。

## 2026-10-31 下载任务列表与进度

下载任务使用有书名、来源标记、状态、创建/更新时间及操作的分页列表。完成、失败或取消后可确认删除任务记录，保留已入库书籍、附件与阅读记录；正在排队、下载、入库的任务不得删除。后端执行当前用户所有权和终态检查，与同用户重试串行，不能仅隐藏按钮。

番茄采用固定下载器 v2.4.15 的 progress.saved_chapters/chapter_total，起点及通用公开章节按实际成功写入章节数报告。未知总数显示等待状态，不按时间伪造百分比；区分获取目录、正文下载、EPUB生成校验、入库及完成。进度条百分比表示章节下载，入库结果以任务状态为准。浏览器刷新可读取当前进度；当前仅一个全局活动下载，内存快照只占一个槽位、按任务和用户隔离，结束即释放，不高频写数据库。应用重启不保留瞬时百分比，沿用既有中断状态和重试机制，不宣称进度断点持久化。

## 2026-10-31 开关、共享阅读字体与导入验重

小说下载来源使用与上方提供商一致的滑动开关，保持键盘操作、独立下载开关、提供商未启用及保存期间禁用语义。服务端字体通过页面导入开放许可的常用中文阅读字体，使用字体数据目录持久化并保留来源、哈希及许可，不随 SPK 升级清空。

新增验重需求已由用户确认：全局默认、每书库可单独覆盖；搜索结果标记已入库并可查看现有书目。再次下载或导入电子书、漫画、有声书时，由用户选择新建、替换同格式文件或追加为同一本书的其他格式。替换保留书目、已保存元数据及阅读记录，不默认覆盖整本书；不同内容文件的位置标记不保证还能对应相同正文。

规则不能仅依赖刮削后的书名、作者和格式。需区分来源编号、有效 ISBN、完整内容哈希等明确标识，以及标题/作者等可能变化的近似线索，提供可配置规则和匹配理由。现有 KOReader 部分 MD5 只能筛选候选，不能冒充完整文件哈希；同名、不同作者、漫画分卷及不同演播版本不得静默归并。用户选择必须经过服务端权限、目标归属、媒体类型和当前文件版本校验，并覆盖上传及下载最终入库路径。覆盖失败保持原文件可恢复，不因 UI 选择直接信任任意路径。

## 2026-10-31 统一重复导入确认（构建前记录）

新增共享 imports 模块：全局默认与书库覆盖、完整 SHA-256/来源编号/有效 ISBN/书名作者规则，跨库受访问权限约束。小说搜索标记已入库或可能已入库；已完成任务记录不再阻止明确的新下载，来源身份另表持久保存。上传、断点上传、小说任务与 Book Dock 批量入库使用明确的新建、追加、替换同格式文件选择；等待选择保留私人暂存或原 Book Dock 单元。书名作者只作可能匹配，不自动合并。

替换保留 bookId、fileId、书目元数据与阅读记录，先验证当前完整文件版本，发布与登记失败可恢复原字节。多文件单元替换只针对界面所示的主文件，其余内容文件追加；界面须明确说明。追加和替换只更新必要的文件技术信息，有声轨先测时长，不覆盖书籍简介或封面。Book Dock 正常发布也使用共享自写登记，避免扫描抢先归属。

本机相关后端 892 项、前端 127 项回归通过；独立 PostgreSQL 16 的迁移/并发 9 项、独立 PostgreSQL 18 完整迁移链及两种组织方式、单文件和分组的真实 HTTP 确认验证已通过。多文件故障允许逐文件重试，整批文件并非一个文件系统原子事务；断电恢复、外部任意程序同时改写等全部组合没有穷举。此条为构建前证据，生产仍是 10034，不能据此宣称新功能已部署。
